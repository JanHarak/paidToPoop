# Chess (Šachy) – implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add chess against the computer to the "Hry" tab. The player picks a colour and a difficulty (Lehká or Těžká), and an unfinished game is saved across page loads.

**Architecture:**
- `<script id="sachy-logika">` holds pure logic, tested in Node: rules, game, notation, storage parsing and engine.
- The engine runs in a Web Worker built from that block's own text, with a main-thread fallback.
- `<script id="sachy-ui">` holds the UI. It mirrors `#pisk-ui`: a grid of `<button>`s, inline in `#hraSlot` or fullscreen via `window.Vrstvy`, and it registers with `window.HrySeznam`.

**Tech Stack:** Plain HTML/CSS/ES5 JS, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-15-sachy-design.md`

## Global Constraints

- Everything lives in the single `index.html`.
  - JS is ES5 style (`var`, `function`).
  - No dependencies, no build step.
  - Czech UI, mobile-first, light and dark mode via the existing CSS variables.
- Never use an em dash in copy, comments or commits.
- Tests run with `node --test` (no directory argument) and load blocks through `tests/load-block.mjs`. 84 tests pass today.
  - Objects from the vm realm must be spread or JSON round-tripped before `deepStrictEqual`.
- Square index is `rank*8 + file`, with a1 = 0, h1 = 7, a8 = 56 and h8 = 63. Colours are `"b"` (white, bílé) and `"c"` (black, černé).
- Moves are exchanged as UCI strings, for example `e2e4` or `e7e8q`. Promotion letters are lowercase `q r b n`.
- localStorage key: `zachodova-sachy-v1`.
  - Value: `{vyhry, prohry, remizy, barva:"b"|"c", obtiznost:"lehka"|"tezka", partie: null | {barva, obtiznost, tahy:[uci...]}}`.
  - Every access is wrapped in try/catch.
  - Corrupt data falls back to the defaults `{0, 0, 0, "b", "lehka", null}`.
- Difficulty:
  - Lehká uses depth 1 to 2 with randomness, and must be beatable.
  - Těžká uses iterative deepening to depth 4 at most, with quiescence and a time limit of 1500 ms. It must never miss a mate in 1 or a free piece.
- The computer moves after a visible delay of about 400 ms. Search must never block the UI when a Worker is available.
- The game must not touch the stopwatch or `zachod` state; it only reads `window.Stopky` for display. Key handlers return early inside `[inert]`. The warning layer (z-index 61/62) stays above the game layer (50).
- Czech piece letters for display: K, D (dáma), V (věž), S (střelec), J (jezdec). Pawns have no letter.

## Review Focus

1. **Move generation correctness.** Castling through or out of check, en passant that exposes the own king, and promotion with capture are covered by the perft positions in Task 1.
2. **Restoring a saved game.**
   - An invalid or illegal UCI list discards the game; it never throws.
   - A restored position where the computer is to move triggers exactly one computer move.
   - Covered in Task 3 (logic) and Task 4 (UI).
3. **Overlapping actions.** Tapping while the computer thinks, closing the game mid-think, or toggling fullscreen mid-think must not produce two computer moves or a move applied to the wrong position.
   - Task 4 uses a search id: results whose id is stale are ignored.
4. **Draw detection.**
   - Threefold repetition counts positions by piece placement, side to move, castling rights and en-passant square.
   - The 50-move rule counts halfmoves.
   - Covered in Task 1 tests.
5. **Lost or missing storage.** If localStorage throws, or the Worker is unavailable (blocked Blob URL), the game is still playable. Task 4 covers the fallback path.

**Interfaces:**
- Produces `window.SachyLogika` with:
  - `START_FEN`
  - `zFen(fen) -> pos` and `doFen(pos) -> string`
    - `pos` is opaque to the UI except `pos.tah`, which is `"b"` or `"c"`.
    - `kusNa(pos, i) -> null | {barva:"b"|"c", typ:"k"|"q"|"r"|"b"|"n"|"p"}`
  - `tahy(pos) -> string[]`: legal moves as UCI.
  - `zahraj(pos, uci) -> pos | null`: returns a new position and does not mutate the input. Returns null if the move is illegal.
  - `vSachu(pos) -> bool`: true if the side to move is in check.
  - `perft(pos, hloubka) -> number`
  - `klic(pos) -> string`: the repetition key (placement, side, castling, en passant).
  - Game functions:
    - `novaPartie() -> partie` and `zTahu(uciList) -> partie | null`
    - `partieTah(partie, uci) -> bool`: mutates `partie`.
    - `partie` = `{pos, tahy:[uci], klice:[klic...], posledni: null | {z, na}}`
    - `stav(partie) -> {konec:bool, vitez:"b"|"c"|null, duvod: null|"mat"|"pat"|"material"|"opakovani"|"50tahu"}`
  - `zapis(pos, uci) -> string`: Czech display notation, using the position before the move.
    - Format: piece letter, from-square, `-` or `x`, to-square.
    - Examples: `"Jg1-f3"`, `"e2-e4"`, `"Dd1xh5"`, `"e7-e8D"` for a promotion, and `"O-O"` / `"O-O-O"` for castling.

### Task 2: Engine and worker glue (`#sachy-logika`, part 2)

**Files:**
- Modify: `index.html`, in the same block.
- Test: `tests/sachy-engine.test.mjs`

**Interfaces:**
- Consumes Task 1.
- Produces:
  - `nejlepsiTah(pos, volby) -> uci`
    - `volby` is `{uroven:"lehka"|"tezka", casMs:number, rnd:() => number, klice?: string[]}`.
    - `klice` is the game history, so the engine scores a repetition that would give a third occurrence as 0.
    - It returns `null` only when there are no legal moves.
  - `spustVWorkeru(text: string) -> void`: called inside the worker. It wires `onmessage` with `{id, tahy:[uci], uroven}`, replays the game with `zTahu`, and posts back `{id, tah}`.
- Algorithm:
  - Negamax alpha-beta.
  - Material values: P 100, N 320, B 330, R 500, Q 900, K 0.
  - A simplified piece-square table, mirrored for black.
  - Move ordering: captures first (MVV-LVA).
  - Quiescence search over captures, Těžká only.
  - Iterative deepening to depth 4 within `casMs`. The best move comes from the deepest completed iteration.
  - Mate scores prefer shorter mates.
  - Lehká:
    - search depth 2 without quiescence;
    - then pick `Math.floor(rnd() * k)` from the top `k = min(4, n)` root moves sorted by score;
    - but if a mate in 1 exists, take it.

- [ ] **Step 1: Write the failing tests.**
  - **Mate in 1**: `6k1/5ppp/8/8/8/8/5PPP/3R2K1 w - - 0 1`. Both levels must answer `d1d8`. Use `rnd = () => 0.99` for Lehká.
  - **Free queen**: `4k3/8/8/3q4/8/8/8/3RK3 w - - 0 1`, where the white rook takes the undefended queen. Těžká must answer `d1d5`.
  - **Finds Scholar's mate**: the position after `e2e4 e7e5 d1h5 b8c6 f1c4 g8f6`, white to move. Těžká must return `h5f7`.
  - **Determinism**: same position, `rnd = () => 0`, same result twice.
  - **Speed**: Těžká on Kiwipete with `casMs: 1500` returns a legal move within 2500 ms in Node.
  - **No moves**: a stalemate position returns `null`.

    - Each cell is labelled e.g. "e4, bílý jezdec" or "e4, prázdné".

  - The board is square: `width: min(100%, 72vh)` inline, filling the available space in fullscreen.
  - Light and dark squares use `--porcelain` and `--grout`.
  - Pieces are the solid glyphs ♚♛♜♝♞♟ (U+265A to U+265F) followed by U+FE0E.
    - White pieces: `--porcelain` fill with an `--ink` text-shadow outline.
    - Black pieces: `--ink`.
  - Highlights:
    - the selected piece: a `--brass` inset;
    - legal targets: a dot, or a ring on capture squares;
    - the last move: `--brass-soft`;
    - the king in check: a red-ish tint using the existing warning colour variable if one exists, otherwise `--brass`.
